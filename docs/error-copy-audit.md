# 全站错误提示文案巡检方案

> 用途：汇总获面通全站各类错误提示，改为自然的人话，避免技术黑话。
> 方法：按模块列出错误场景、当前错误提示、优化建议。

---

## 1. API 连接类

| 错误场景 | 当前提示（参考） | 建议优化 |
|----------|-----------------|----------|
| 401 Key 无效 | 测试连接返回 401 | "Key 不对，检查一下复制粘贴有没有多空格" |
| 402 余额不足 | 测试连接返回 402 | "账号余额不足，去服务商后台充值后再试" |
| 403 无权限 | 测试连接返回 403 | "这个 Key 没有模型权限，可能需要申请白名单" |
| 429 请求太频繁 | 测试连接返回 429 | "请求太频繁了，等 30 秒再试" |
| 网络超时 | 连接超时 | "网络连接超时，检查代理或网络设置" |
| Key 为空 | Key 为空 | "先把 Key 粘贴进来，再测试连接" |

## 7. 通用优化规则

### 规则一：先共情，再给方案
- ✅ "Key 不对？重新复制粘贴试试"
- ❌ "错误代码 401"

### 规则二：说人话，不说状态码
- ✅ "余额不够了，去充个值"
- ❌ "402 Payment Required"

### 规则三：给下一步操作
- ✅ "麦克风没声音？先检查权限 → 再试本地诊断"
- ❌ "麦克风故障"

### 规则四：避免重复的技术上下文
- ✅ "连不上 Deepgram"
- ❌ "Deepgram WebSocket 连接异常，onError 回调触发"

## 8. 巡检路线

1. 打开应用，逐页触发错误场景
2. 截图记录每个错误提示
3. 对照本文件检查是否符合人话标准
4. 将需要修改的条目记录到 `docs/deepseek-third-wave-plan.md` 或 `product-optimization-backlog.md`

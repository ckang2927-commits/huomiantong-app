### 1.1 软件介绍

获面通是一款 Windows 桌面面试辅助工具，帮助你：

- **实时转写**面试官提问（支持麦克风和电脑音频）
- **AI 生成回答建议**，基于你的简历和岗位 JD
- **模拟训练**，提前练习常见面试问题
- **保存和回顾**面试会话记录，导出为 Markdown 或 Word

所有数据存储在本地，不经过第三方服务器（除你配置的 API 服务商外）。

### 1.2 安装与启动

#### 1.2.1 系统要求

- Windows 10 / Windows 11（64 位）
- 稳定的网络连接（用于 API 调用和语音转写）
- 麦克风（用于语音转写，可选）
- 至少 4GB 可用内存

#### 1.2.2 安装步骤

1. 双击安装包 `获面通 Setup x.x.x.exe` 进行安装。
2. 安装完成后，桌面会出现"获面通"快捷方式。
3. 双击快捷方式启动应用。

#### 1.2.3 首次启动

首次启动后，你将看到：

- 左侧导航栏：面试台、模拟训练、作战室、简历库、设置、会话记录
- 默认进入**面试台**页面
- 顶部显示当前候选人和岗位信息

> **建议顺序**：先配置 API → 导入简历 → 再去面试台

### 1.3 API 配置

使用 AI 回答生成和 Deepgram 语音转写前，需要先配置 API Key。

#### 1.3.1 进入设置

点击左侧导航栏的**设置**图标，进入设置页面。

#### 1.3.2 配置回答模型

获面通支持以下 AI 提供商：

| 提供商 | 推荐模型 | 说明 |
|--------|---------|------|
| DeepSeek | deepseek-v4-flash / deepseek-v4-pro | 速度快，性价比高 |
| 阿里百炼 DashScope | qwen3.7-plus / qwen3.7-max | 国内直连，低延迟 |
| OpenAI | gpt-4.1-mini / gpt-4.1 | 国外服务，需网络条件 |
| Anthropic | claude-3-5-haiku-latest / claude-3-5-sonnet-latest | 长上下文表现优秀 |

配置步骤：

1. 在"回答模型与风格"区域选择你要用的**提供商**。
2. 填写 **API Key**（从对应平台获取）。
3. 可以修改 **Base URL**（如果你使用代理中转 API）。
4. 选择**模型名称**。
5. 点击**测试连接**验证配置是否正确。
6. 点击**保存设置**。

#### 1.3.3 配置 Deepgram 语音

在"提供商列表"中找到 Deepgram：

1. 填写 Deepgram API Key（从 deepgram.com 获取）。
2. 点击**测试连接**验证。
3. 保存设置。

#### 1.3.4 配置回答风格

在设置中可以选择 AI 回答风格：

- **fast（极速短答）**：简短直接，适合快速过问题
- **standard（标准回答）**：结构完整，适合正式面试
- **star（STAR 详细版）**：STAR 法则展开，适合行为面试

#### 1.3.5 面试模式

选择目标岗位类型，AI 会根据岗位特点生成更相关的问题和答案：

- 数据分析岗、AI 产品经理岗、后端开发岗、前端工程师岗、全栈工程师岗、通用面试

#### 1.3.6 JD 编辑器

在设置页可以编辑**岗位 JD（职位描述）**：

- 可以直接粘贴 JD 文本
- 点击"按简历生成"从候选人简历生成 JD
- 点击"AI 深度生成"用 AI 生成详细 JD
- 修改 JD 后可以看到**简历-JD 匹配评分**

### 1.4 导入简历

#### 1.4.1 进入简历库

点击左侧导航栏的**简历库**图标。

#### 1.4.2 新增候选人

1. 点击**新增候选人**按钮。
2. 填写候选人姓名和应聘岗位。
3. 点击**保存简历**。
4. 支持多个候选人，可以搜索切换。

#### 1.4.3 上传简历文件

支持三种简历类型：

| 类型 | 说明 | 支持格式 |
|------|------|---------|
| 正式简历 | 浓缩版简历（1-2 页） | PDF、DOCX、MD |
| 万字简历 | 详细经历解释版 | DOCX、MD |
| 其他简历 | 补充材料 | 所有格式 |

上传后，AI 回答会基于这些简历内容生成依据。

#### 1.4.4 保存设置

修改简历后，记得点击右上角的**保存简历**按钮。

### 1.5 面试台使用

面试台是获面通的核心页面。

#### 1.5.1 手动输入问题

1. 在下方输入框中输入面试官的问题。
2. 按回车或点击**生成回答**按钮。
3. AI 会先生成等待话术，再展示正式回答。
4. 回答下方会显示**简历依据来源**和**编造风险提示**（如有）。

#### 1.5.2 面试模式切换

- **自动回答**：开启后，每次识别到完整问题会自动生成回答。
- **模拟面试**：开启后系统会按顺序自动追加问题。

#### 1.5.3 预热缓存

面试台顶部有**预热缓存**区域：

- 点击"生成预热答案"可提前缓存常见问题的回答
- 面试时如果遇到类似问题，可以直接使用缓存答案，响应更快

#### 1.5.4 回答展示

回答面板包含：

- **等待话术**：生成中的过渡话术（随机展示）
- **正式答案**：完整的 AI 生成回答
- **依据来源**：标记了回答依据来自哪份简历
- **编造风险提示**：如果 AI 可能编造了简历中没有的信息
- **延迟报告**：首字延迟和总耗时

### 1.6 语音转写

#### 1.6.1 语音设置

在面试台左侧的"语音设置"面板：

- **麦克风设备**：选择要使用的麦克风
- **刷新设备**：重新枚举可用设备
- **授权麦克风**：打开系统麦克风权限设置
- **状态指示**：显示 Deepgram 连接状态、连接延迟、输入音量

#### 1.6.2 麦克风转写

1. 确保已配置 Deepgram API Key。
2. 点击**麦克风按钮**开启转写。
3. 面试官说话时，实时转写会显示在面板中。
4. 再次点击按钮停止转写。

#### 1.6.3 电脑音频转写

用于转写电脑播放的音频（如远程面试中的声音）：

1. 点击**电脑音频按钮**。
2. 选择要捕获的屏幕/窗口来源。
3. 开始转写。
4. 再次点击按钮停止。

#### 1.6.4 转写过滤

系统会自动过滤掉"嗯、啊、能听到吗、太慢了"等无效片段，不会进入会话记录，也不会触发 AI 回答。

#### 1.6.5 本地麦克风诊断

如果不确定麦克风是否正常工作：

1. 在语音设置中点击**本地麦克风诊断**。
2. 系统会检查麦克风能否打开、是否有输入音量。
3. 会显示具体诊断结果（不调用 Deepgram）。

### 1.7 模拟训练

#### 1.7.1 开始训练

1. 点击左侧导航栏的**模拟训练**图标。
2. 选择训练类型/模板。
3. 选择问题数量（10 / 15 / 20 题）。
4. 点击**开始训练**。

#### 1.7.2 训练模板

内置模板：

- **数据分析**：指标、SQL、业务分析
- **AI 产品**：AI 场景、落地、指标
- **前端**：组件、性能、体验
- **全栈**：前后端、部署、系统
- **后端**：系统、接口、稳定性
- **压力面**：高强度连续提问

也可以**自定义模板**，设置名称、岗位标签、JD、题数和固定题纲。

固定题纲支持一行一题，训练时会优先从固定题纲出题。

#### 1.7.3 回答问题

1. 看到问题后，在回答框中输入你的回答。
2. 也可以点击**语音作答转写**用麦克风口述。
3. 提交回答后，AI 会给出**点评和分数**。
4. 右侧显示**参考答案**（基于你的简历和岗位 JD）。

#### 1.7.4 口语表达评分

语音作答后，系统会分析：

- 语速
- 清晰度
- 结构感
- 稳定感
- 口头禅数量
- 停顿提示
- 作答时长

评分会随训练记录保存，并写入导出文件。

#### 1.7.5 朗读功能

- **朗读问题**：点击可朗读当前面试问题
- **自动朗读下一题**：开启后自动朗读下一题
- **朗读答案**：朗读参考答案

#### 1.7.6 训练复盘

完成所有题目后：

1. 系统生成**最终复盘报告**。
2. 展示**薄弱点排行榜**，每个薄弱点有"待提升指数"和练习建议。
3. 可以点击**下一轮练这个**，针对薄弱点开启专项训练。
4. 训练成绩趋势显示最近多轮成绩走势。

#### 1.7.7 错题收藏

- 低于 75 分的题目自动收入**错题收藏夹**。
- 支持手动收藏题目。
- 可以从收藏夹生成错题专项训练。

#### 1.7.8 草稿功能

- 训练过程中自动保存草稿，意外退出后自动恢复。
- 支持手动保存、清除草稿。

#### 1.7.9 保存与导出

- **保存到会话记录**：训练记录出现在历史会话中。
- **导出 MD**：导出为 Markdown 文件。
- **导出 Word**：导出为 Word 文档（含口语评分）。

### 1.8 会话记录

#### 1.8.1 查看会话

点击左侧导航栏的**会话记录**图标：

- 显示所有已保存的会话（面试 + 训练）。
- 顶部看板显示高频题型、质量、风险等统计信息。
- 可按候选人筛选会话。

#### 1.8.2 操作会话

支持：

- **打开**：查看会话的详细问答记录。
- **重命名**：改会话标题。
- **导出 MD / Word**：导出单个会话。
- **批量导出**：选中多个会话批量导出。
- **删除**：单条或批量删除。

#### 1.8.3 会话内容

打开的会话会显示：

- 问题时间线、面试官问题和 AI 回答
- 回答的依据来源标签

### 1.9 面试前体检（作战室）

#### 1.9.1 进入作战室

点击左侧导航栏的**作战室**图标（盾牌图标）。

#### 1.9.2 一键检查

点击**开始一键检查**，系统会检测：

- 候选人简历是否就绪
- 回答模型是否配置正确
- Deepgram 语音服务是否可用
- 麦克风/电脑音频是否支持
- 悬浮窗是否可用
- 预热缓存是否就绪

#### 1.9.3 诊断日志

作战室下方显示诊断日志面板，记录：

- API 服务商测试失败记录
- Deepgram 连接异常
- 麦克风/电脑音频问题
- 每条日志有人话解释和操作建议

点击错误弹窗的"查看详情"也会跳转到此区域。

### 1.10 备份与恢复

#### 1.10.1 导出备份

在设置页面：

1. 点击**导出备份**。
2. 选择是否包含 API Key（注意安全）。
3. 保存 JSON 备份文件。

备份包含：设置、会话记录、用量数据。

#### 1.10.2 导入备份

1. 点击**导入备份**。
2. 选择备份 JSON 文件。
3. 确认覆盖后导入。
4. 导入后设置、会话、用量都会刷新。

> 建议定期导出备份，特别是在重大配置变更前后。

### 1.12 常见问题

#### Q: 为什么测试连接失败？

- 检查 API Key 是否填写正确。
- 检查网络是否能访问 API 服务商（部分国外服务需要科学上网）。
- 检查 Base URL 是否正确（特别是使用代理中转时）。
- 详细错误解释见本文档"第三部分：错误解释词典"。

#### Q: 麦克风转写没有反应？

1. 在语音设置中检查 Deepgram 是否配置且测试通过。
2. 检查系统麦克风权限是否已授予。
3. 使用"本地麦克风诊断"检查硬件是否正常。
4. 尝试切换麦克风设备。

#### Q: 怎么保存面试内容？

在面试台点击**保存会话**，输入会话名称后保存。

#### Q: 数据安全吗？

- 所有数据存储在本地计算机。
- API Key 使用系统加密存储（safeStorage）。
- AI 回答只发送到你配置的 API 提供商。
- 开启隐私模式后，导出和悬浮窗会隐藏敏感信息。

#### Q: 没有 API Key 能用吗？

- 面试台需要 API Key 才能生成 AI 回答。
- 模拟训练可以在没有 API Key 时进入"本地兜底训练"模式。
- 语音转写需要 Deepgram API Key。
- 建议至少准备一个 AI API Key 和一个 Deepgram API Key。

#### Q: 支持哪些面试岗位？

数据分析、AI 产品经理、后端开发、前端工程师、全栈工程师和通用面试。

#### Q: 怎么卸载？

通过 Windows 设置 → 应用 → 找到"获面通"并卸载。备份文件会被删除，建议先导出备份。

### 2.3 分区一：API 与模型配置

#### 2.3.1 字段说明

| 字段 | 类型 | 默认值 | 说明 | 保存方式 |
|------|------|--------|------|---------|
| API Key | string | "" | 各平台的 API 密钥 | safeStorage 加密保存 |
| Base URL | string | 各平台默认 | API 请求地址，支持代理中转 | 明文保存 |
| 模型名称 | string | 各平台推荐 | 使用的模型标识 | 明文保存 |
| 启用状态 | boolean | true（DeepSeek/Deepgram）/ false（其他） | 是否启用该提供商 | 明文保存 |
| 金额预算 | number | 0（不限） | 金额预算上限（元） | 明文保存 |
| 测试连接 | - | - | 验证当前配置是否可用 | 不保存 |

#### 2.3.2 支持的提供商

| 提供商 ID | 显示名称 | 类型 | 默认 Base URL |
|-----------|---------|------|--------------|

### 3.1 HTTP 状态码错误

#### 401 Unauthorized

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接返回"401 · xx ms"；生成回答时提示模型连接失败 |
| **原因** | API Key 无效、已过期、或类型不匹配（例如把 Deepgram 的 Key 填到了 DeepSeek 的字段里） |
| **解决办法** | 1. 检查 API Key 是否复制完整（不要漏字符）<br>2. 确认 Key 没有过期（登录提供商后台查看）<br>3. 确认选对了提供商（不要把阿里百炼的 Key 填到 DeepSeek 的字段）<br>4. 重新复制粘贴 Key 后再次测试 |

#### 402 Payment Required

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接返回"402 · xx ms"；麦克风转写突然断开 |
| **原因** | API 余额不足、免费额度过期、或账单未开通。Deepgram 经常在免费额度用完后返回 402 |
| **解决办法** | 1. 登录 API 提供商后台，检查账户余额和账单状态<br>2. Deepgram 用户：检查是否绑定了信用卡<br>3. 阿里百炼用户：检查是否开通了对应模型服务<br>4. 充值或升级套餐后重新测试 |

#### 403 Forbidden

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接返回"403 · xx ms" |
| **原因** | API Key 没有该模型/服务的访问权限；或账户被限制 |
| **解决办法** | 1. 确认该 API Key 有调用目标模型的权限<br>2. 检查是否在提供商后台开启了模型访问<br>3. 部分模型需要单独申请白名单（如 Claude 3.5 Sonnet） |

#### 404 Not Found

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接返回"404 · xx ms" |
| **原因** | Base URL 或模型名称错误，API 地址不存在 |
| **解决办法** | 1. 检查 Base URL 末尾是否缺少 `/v1` 等路径<br>2. 检查模型名是否正确（注意大小写和版本号）<br>3. 如果使用代理中转，确认中转地址是否有对应路由 |

#### 429 Too Many Requests

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接返回"429 · xx ms"；使用时突然频繁报错 |
| **原因** | 请求频率超过 API 限制（RPM/TPM 超限）或预算超限 |
| **解决办法** | 1. 等待 1-2 分钟后重试<br>2. 降低使用频率（减少同时生成答案的数量）<br>3. 在提供商后台升级套餐以提高限额<br>4. 检查是否设置了金额预算并已超限 |

### 3.2 Deepgram 语音错误

#### Deepgram 连接超时

| 项目 | 内容 |
|------|------|
| **用户看到** | 麦克风按钮监听中但一直没反应；语音设置显示"Deepgram 连接失败" |
| **原因** | 网络无法连接到 Deepgram API，或被防火墙/代理拦截 |
| **解决办法** | 1. 检查网络连接<br>2. 确认 Deepgram API Key 配置正确<br>3. 某些网络环境需要配置代理才能访问 Deepgram<br>4. 点击"测试连接"确认 Deepgram 是否可达 |

#### Deepgram 余额不足（402）

| 项目 | 内容 |
|------|------|
| **用户看到** | 转写过程中突然停止；提示"Deepgram 返回 402" |
| **原因** | Deepgram 免费额度（$200）用尽 |
| **解决办法** | 1. 登录 deepgram.com 查看用量和账单<br>2. 绑定信用卡或充值<br>3. 如果暂时不想付费，可以先关闭麦克风转写，手动输入问题 |

#### Deepgram WebSocket 异常断开

| 项目 | 内容 |
|------|------|
| **用户看到** | 实时转写突然不更新了；按钮状态还在"监听中" |
| **原因** | 网络波动、长时间无音频输入导致连接超时、或服务端错误 |
| **解决办法** | 1. 停止转写后重新开始<br>2. 检查网络稳定性<br>3. 如果频繁断开，尝试切换网络环境 |

### 3.3 麦克风/音频设备错误

|------|------|
| **用户看到** | 已获取权限但音量条不动；麦克风诊断提示无输入 |
| **原因** | 麦克风被静音、设备未插好、或选择了错误的设备 |
| **解决办法** | 1. 检查麦克风物理开关是否打开<br>2. 检查系统音量设置中麦克风是否被静音<br>3. 在语音设置中尝试切换其他麦克风设备<br>4. 使用"本地麦克风诊断"排查 |

#### 电脑音频不支持

| 项目 | 内容 |
|------|------|
| **用户看到** | 点击电脑音频按钮后提示"当前系统不支持" |
| **原因** | 操作系统或音频驱动不支持屏幕/窗口音频捕获 |
| **解决办法** | 1. 确保 Windows 版本 >= 10 1903<br>2. 更新音频驱动<br>3. 如果仍然不支持，可以改用麦克风转写或手动输入问题 |

#### 电脑音频未选择来源

| **原因** | 未选择要捕获的屏幕或窗口 |

### 3.4 网络与连接错误

#### 网络超时

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接长时间不返回；生成回答时一直"生成中..." |
| **原因** | 网络不可用、DNS 解析失败、或 API 服务被屏蔽 |
| **解决办法** | 1. 检查网络是否正常（浏览器能否打开网页）<br>2. 如果使用国外 API，可能需要科学上网<br>3. 检查 Base URL 是否能 ping 通<br>4. 考虑切换为国内 API（如阿里百炼） |

#### ECONNREFUSED（连接被拒绝）

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接提示"连接被拒绝" |
| **原因** | Base URL 端口错误、或目标服务器拒绝连接 |
| **解决办法** | 1. 检查 Base URL 的协议（http vs https）和端口<br>2. 如果使用本地代理，确认代理服务正在运行<br>3. 确认 API 服务商没有故障 |

#### SSL/TLS 错误

| 项目 | 内容 |
|------|------|
| **用户看到** | 测试连接提示证书相关错误 |
| **原因** | 代理或中间人劫持了 HTTPS 连接；系统时间不正确 |
| **解决办法** | 1. 检查系统时间是否正确<br>2. 如果使用自签名证书的代理，取消 SSL 验证（不推荐）<br>3. 避免使用公共 WiFi 或不可信网络 |

| **用户看到** | 测试连接提示"model not found"或类似错误 |

| 项目 | 内容 |
|------|------|
| **用户看到** | 生成回答时反复失败；但测试连接正常 |
| **原因** | 模型服务端负载高，暂时无法处理请求 |
| **解决办法** | 1. 稍等几分钟后重试<br>2. 尝试切换另一个模型版本<br>3. 暂时切换到其他提供商 |

#### 上下文超长

| 项目 | 内容 |
|------|------|
| **用户看到** | 生成回答时报错，提示超出上下文限制 |
| **原因** | 简历+JD+历史会话总长度超过了模型的上下文窗口 |
| **解决办法** | 1. 压缩简历内容（减少冗余描述）<br>2. 使用长上下文模型（如 Claude 或 DeepSeek v4 Pro）<br>3. 开启新会话，减少历史累积 |

### 1. 403 Forbidden

# 附录：用户手册补充（F5 后续补充）

> 基于使用反馈补充的常见操作场景

## 场景一：第一次使用，我应该先做什么？

1. **配置 API Key** → 进入设置，至少配置 DeepSeek（或阿里百炼）和 Deepgram
2. **创建候选人** → 进入简历库，新增候选人并上传正式简历
3. **选择岗位** → 在设置中选择目标岗位类型（如数据分析岗）
4. **开始面试** → 回到面试台，输入问题或开启麦克风转写

## 场景二：面试过程中需要临时调整什么？

- **切换候选人**：点击面试台顶部的候选人卡片，从列表中选择
- **开关自动回答**：点击面试台顶部的自动回答开关
- **调整麦克风音量**：在语音设置面板中查看输入音量条，调整系统麦克风音量
- **打开悬浮窗**：按 `Ctrl + H` 或点击顶部悬浮窗按钮

## 场景三：如何复盘一场面试？

1. 面试结束后点击**保存会话**，命名后保存
2. 进入**会话记录**，找到刚保存的会话并打开
3. 查看问答时间线，可以看到每个问题的回答和依据来源
4. 可以**导出 MD 或 Word** 保存到本地
5. 多场面试后，顶部看板会自动统计高频题型和质量趋势

## 场景四：模拟训练和面试台有什么区别？

| 维度 | 面试台 | 模拟训练 |
|------|--------|---------|
| 使用场景 | 真实面试或一对一练习 | 自主刷题练习 |
| 问题来源 | 面试官提问或手动输入 | AI 自动出题（可固定题纲） |
| 是否有评分 | 无评分，但会显示编造风险 | 每道题 AI 点评打分 |
| 复盘 | 手动保存后到会话记录查看 | 自动生成复盘报告+薄弱点分析 |
| 语音 | 转写面试官语音 | 口头作答转写 |

## 场景五：我的数据会丢失吗？

- 正常使用时数据会持久保存在本地
- 建议定期通过设置页的**导出备份**功能保存备份
- 卸载软件前务必导出备份，卸载后会删除本地数据
- 更新版本时一般不会丢失数据（除非明确说明）

## 场景六：为什么有些回答显示"编造风险"？

当 AI 的回答内容在候选人简历中没有找到对应依据时，系统会标记"编造风险"。这是为了提醒你不要在面试中使用没有实际经历支撑的内容。建议：

- 尽量丰富简历内容（特别是万字简历）
- 回答时结合自己的实际经历
- 如果 AI 编造了内容，手动修改后再使用

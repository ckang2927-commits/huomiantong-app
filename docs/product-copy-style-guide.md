# 全局产品文案风格指南

> 用途：统一获面通全站的文案语气、风格和术语，避免不一致。

---

## 1. 核心原则

### 自然口语化
- 像人在说话，不像说明书。
- ✅ "输入你的 API Key"
- ❌ "请输入有效的 API 认证密钥"

### 简短直接
- 能 5 个字说完不用 10 个字。
- ✅ "保存成功"
- ❌ "您的设置已成功保存到本地存储"

### 不说技术黑话
- 用户不需要懂技术细节。
- ✅ "Key 不对，检查一下"
- ❌ "401 Unauthorized：API 认证令牌验证失败"

### 有温度
- 错误时先表示理解，再给解决办法。
- ✅ "麦克风没声音？先检查权限，再试一下本地诊断。"
- ❌ "错误：设备未找到"

## 2. 术语统一表

| 统一用词 | 不要用 |
|----------|--------|
| 面试台 | 工作区、主工作台 |
| 作战室 | 体检中心、健康检查 |
| 模拟训练 | 练习模式、面试练习 |
| 会话记录 | 历史记录、聊天记录 |
| 简历库 | 简历管理 |
| 悬浮窗 | 小窗口、浮动窗口 |
| 候选人 | 用户、档案 |
| API Key | 密钥、API 密钥 |
| 测试连接 | 连接测试、验证连接 |
| 生成 | 提交、开始 |
| 保存 | 存储、存档 |
| 删除 | 移除、清除 |
| 导出 | 输出、下载 |
| 导入 | 上传、加载 |

## 3. 按钮文案规范

- **操作按钮**：动词 + 名词，如"导出 MD"、"保存设置"
- **确认按钮**："确认删除"、"确定覆盖"
- **取消按钮**：统一用"取消"
- **链接按钮**：用"查看详情"、"去设置"等行动指引
- 不要用"确定"作为通用按钮（太模糊）

## 4. 提示文案规范

### 成功提示
- 格式：`[操作]成功`
- 示例："保存成功"、"导出成功"、"测试连接通过"
- 不加感叹号（除非用户操作后有惊喜感）

### 错误提示
- 格式：`[问题] + [原因/解决办法]`
- 示例："Key 不对，重新复制粘贴试试"
- 不推卸责任，不说"系统错误"

### 空状态提示
- 格式：`[当前状态] + [建议操作]`
- 示例："还没有会话记录，保存一次面试看看吧"
- 不直接用"暂无数据"（太冷）

### 加载/等待提示
- 用"生成中..."、"正在保存..."
- 不加"请等待"（用户已经在等了）

## 5. 常见错误文案（人话版）

| 技术原文 | 人话版 |
|----------|--------|
| 401 Unauthorized | Key 不对，检查一下有没有复制完整 |
| 402 Payment Required | 账号余额不足，去服务商后台充值 |
| 403 Forbidden | 这个 Key 没有模型权限，检查是否需申请白名单 |
| 429 Too Many Requests | 请求太频繁，等 30 秒再试 |
| Deepgram connection timeout | Deepgram 连接超时，检查网络或者 Key 对不对 |
| Device not found | 找不到麦克风，检查设备连接和权限 |
| Network error | 网络好像断了，检查一下能不能上网 |

## 6. 语气温度等级

| 场景 | 温度 | 示例 |
|------|------|------|
| 成功/提示 | 温暖 | "保存成功，放心了~" |
| 信息说明 | 中性 | "支持 3 种回答风格" |
| 警告/注意 | 温和 | "删除后不能恢复，确定吗？" |
| 错误 | 理解+帮助 | "Key 不对？重新复制粘贴试试" |
| 空状态 | 鼓励 | "还没有会话，开始第一次面试吧" |

## 7. 标点规范

- 中文文案统一用中文标点（，。！？）
- 英文/代码片段保持英文标点
- 句子末尾加句号（标题、按钮可以不加）
- 提示文案可以用问号开头表示关心（如"Key 不对？"）

## 8. 不一致检查清单

每次修改文案时检查：
- [ ] 术语是否和术语表一致
- [ ] 语气是否符合场景温度
- [ ] 长度是否够短（中文不超过 30 字/句）
- [ ] 是否正确使用中文标点
- [ ] 是否有技术黑话可以优化

# 获面通：发布与回归执行指南

> 每次发布前和执行修改后的验收流程。

---

## 一、发布前检查清单

在打包给朋友使用前，按以下顺序逐项确认：

### 1. 构建检查
- [ ] 运行 `npm run build`，确保无错误
- [ ] 运行 `npm run dev` 启动应用，确认白屏/闪退
- [ ] 检查 `out/` 目录是否正常生成

### 2. API 与网络
- [ ] 至少准备一个有效的 API Key（DeepSeek / 阿里 / OpenAI / Anthropic 均可）
- [ ] Deepgram API Key 已配置（如需语音转写）
- [ ] 确认各服务商测试连接通过
- [ ] 预算和用量设置合理

### 3. 数据备份
- [ ] 导出一份完整备份（设置 → 备份 → 导出）
- [ ] 确认备份 JSON 文件可正常读取

### 4. 隐私检查
- [ ] 隐私模式开关按需设置
- [ ] 确认导出内容脱敏效果符合预期
- [ ] 本地数据目录 `%APPDATA%/huomiantong/` 不包含意外暴露的敏感信息

### 5. 构建与打包
- [ ] `npm run build` 通过
- [ ] 打包命令 `npm run dist` 执行成功（如已配置）
- [ ] 安装包 exe 文件正常生成
- [ ] 在另一台电脑上测试安装和运行

### 6. 文档更新
- [ ] `docs/release-notes-template.md` 已填写本次版本内容
- [ ] `docs/known-issues.md` 已更新当前已知问题
- [ ] `docs/README.md` 文档索引状态已更新

## 二、修改后回归测试

### 确定影响范围

| 修改类型 | 影响范围 | 建议回归模块 |
|---------|---------|-------------|
| API/模型相关 | 回答生成、测试连接、预算统计 | API 设置、面试台 |
| 语音相关 | 麦克风、电脑音频、Deepgram | 面试台语音、训练语音 |
| 简历相关 | 简历上传、候选人管理 | 简历库、面试台 |
| 训练相关 | 模拟训练、拟真面试 | 训练页 |
| 会话相关 | 保存、查看、导出 | 会话记录 |
| UI 调整 | 布局、样式、文案 | 受影响页面 + 通用 UI |
| 数据存储 | 备份、设置保存 | 备份、设置 |

### 回归执行流程

1. **确定本次修改范围和影响模块**
2. **运行 `npm run build`** 确认构建通过
3. **运行 `npm run dev`** 启动应用
4. **按对应人工验收脚本逐项点测**：
   - 主窗口验收：`docs/manual-test-main-window.md`
   - API 设置验收：`docs/manual-test-api-settings.md`
   - 语音链路验收：`docs/manual-test-audio.md`
   - 悬浮窗验收：`docs/manual-test-floating-window.md`
   - 导入导出验收：`docs/manual-test-import-export.md`
5. **记录测试结果**：使用 `docs/regression-run-template.md`
6. **发现问题**：记录到已知问题或修复后再验证

### 快速回归（修改范围明确时）

如果只改了单个模块（例如只改了 API 设置页），至少需要点测：

- 被修改模块的所有功能点
- 与被修改模块有交互的相邻模块
- 应用整体能正常启动和导航

## 三、打包后验收

打包成安装包后，还需要额外验收：

- 安装过程是否正常（含 SmartScreen 处理）
- 首次启动是否正常（含数据目录创建）
- 打包版功能是否与开发版一致
- 详细打包后验收脚本：`docs/packaged-app-regression.md`

## 四、版本发布

1. 填写 `docs/release-notes-template.md`
2. 确认版本号更新
3. 生成安装包
4. 通知朋友/用户升级
5. 记录本次回归测试结果到 `docs/regression-run-YYYY-MM-DD.md`

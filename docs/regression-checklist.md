# 获面通功能回归清单

每次修复、新增功能或准备发版前，先运行 `npm run build`。如果本次明确要发布，再额外运行 `npm run dist` 并做安装版点测。

## 面试台

- 运行 `npm run validate:rag`，确认第一家公司、上一家公司、RFM、转化漏斗和多候选人隔离样例通过。
- 运行 `npm run validate:queue`，确认连续问题 FIFO 排队、答案完成后继续下一题、缓存命中继续下一题和队列重置通过。
- 打开应用后能进入面试台，左侧导航、顶部状态和主要按钮正常显示。
- 手动输入问题后点击生成，先出现等待话术，再出现模型答案或本地兜底答案。
- 回答依据优先命中正式简历、万字简历或其他简历里的相关片段。
- 自动回答开关、暂停/继续接收转写、开始新会话都能切换，并有明确提示。
- 未配置 Deepgram Key 时，麦克风/电脑音频转写给出中文提示，不出现乱码。
- 麦克风、电脑音频、设备刷新、权限授权、连接状态和音量条不应卡死或无限加载。
- 保存会话会弹出命名输入，保存后能在会话记录中看到。

## 新手引导

- 运行 `npm run validate:onboarding-tour`，确认漫游步骤、目标锚点、点击锁定、粗略/详细说明和下一步/跳过约束通过。
- 新用户首次打开会出现新手引导，老用户不会反复弹出。
- 点击关闭按钮后引导消失，设置里能重新打开教程。
- 引导会自动切换到面试台、训练、拟真面试、作战室、简历库、会话记录、面试复盘、帮助中心和设置子模块。
- 面试台引导应分别介绍当前候选人、目标岗位、实时转写、AI 建议回答、回答策略、语音设置和面试预热题目；预热题目要明确说明它是面试前素材，不是可直接点开的实时问题。
- 目标区域有镂空高亮，页面其余区域不能点击；引导浮窗只允许“下一步”和“跳过引导”。
- 点击面试台“目标岗位”应跳转简历库并闪烁目标岗位字段；点击“当前候选人”应跳转并闪烁姓名字段。
- 点击顶部 Deepgram 状态应跳转设置中心语音转写区域并闪烁；点击 DeepSeek/当前回答模型状态应跳转对应模型卡片并闪烁。
- 完成回答模型、语音转写、简历、模拟训练、拟真面试后，新手任务进度能自动更新。
- 关闭应用再重新打开后，引导进度仍然保留，不应从头反复打扰用户。

## API 与设置

- DeepSeek、阿里、OpenAI、Anthropic、Deepgram 的 Key、Base URL、模型名可以保存，并在重启后读回。
- 测试连接能显示成功、失败和延迟，不应一直 loading。
- 401、402、403、404、429 等错误要显示中文原因；402 要提示余额不足、免费额度过期或账单未开通。
- API 配置新手卡片里的官网链接能打开，外链失败时有可见提示。
- 设置目录中“诊断日志”下面有“更新日志”入口。

## 模拟训练

- 可以选择训练模板和题目数量，开始训练后能生成第一题。
- 没有 API Key 时进入本地兜底训练，不应空白。
- 用户回答记录支持手动输入和修改。
- 参考答案默认不应压迫用户作答，展开/收起状态清楚。
- 提交答案后显示点评、分数和下一题。
- 完成所选题数后生成最终复盘，并可保存到会话记录。

## 拟真面试

- 运行 `npm run validate:realistic`，确认配置归一化、题库覆盖、难度/侧重点选题和已用题排除通过。
- 拟真面试配置面板可见，岗位、题数、难度、侧重点、面试官风格可调整。
- 三套本地面试官声音可选择，试听按钮有反馈。
- 本地声音不可用时回退系统语音，不应导致页面崩溃。
- 语音作答转写和手动作答都能进入训练流程。
- 保存配置后重新进入页面，配置值保持不变。

## 面试复盘

- 运行 `npm run validate:review`，确认模拟转写文本的问题提取、回答切片、题型评分、本地报告和说话人格式兼容通过。
- 运行 `npm run validate:deep-report`，确认 AI 深度报告无 Key 和模型失败时会退回本地草案。
- 运行 `npm run validate:deep-talk`，确认 AI 深度话术无 Key、模型失败、空回答和无可优化问题时有可见兜底。
- 运行 `npm run validate:long-audio`，确认 20/60 分钟长录音的分段、漏题、发言人和失败重试建议通过。
- 上传真实录音后能转写、编辑说话人、重新提取问题并生成本地复盘报告。
- HR 意愿/稳定性问题不应按项目指标硬扣分，项目经历题应保留业务证据评分。
- 复盘记录可保存、删除，并可导出 Markdown/Word。

## 更新日志与自动更新

- 运行 `npm run validate:update-flow`，确认检查、下载、重启安装三步不会被合并成自动下载。
- 设置里的“更新日志”能查看待发布内容、历史版本、发布时间和完整日志。
- 点击“检查更新”只检查版本，不应自动下载。
- 有新版本时先让用户选择是否下载。
- 下载完成后再由用户选择“重启安装”。
- 开发模式下检查更新应提示不会连接正式更新源。
- 覆盖更新后，API Key、简历、会话、复盘记录和预算记录仍然保留。

## 文档与帮助中心

- 帮助中心能搜索到 `quick-start.md`、`new-user-guide.md`、`update-release-guide.md`、`release-notes-v0.1.4.md`。
- 打开的用户文档不能出现 `闂`、`閼`、`缁`、`閳` 等乱码字符。
- 版本说明中的入口应统一为“设置 -> 更新日志”。
- 发布前运行 `npm run docs:index`，确保帮助中心索引是最新的。

## 打包发布

- 准备发布前必须确认版本号高于线上版本，不能重复使用已经发布过的版本号。
- 运行 `npm run validate:release-resources`，确认 Piper 正式资源、extraResources 配置和临时文件归档状态通过。
- 打包前清理或归档 `.tmp-*`、主题预览图、临时截图、probe 音频等测试文件。
- Piper 资源只保留正式运行需要的模型、可执行文件、DLL 和数据目录。
- 安装包能正常安装、首次启动、覆盖安装和卸载。
- 当前 Windows 安装包未做代码签名，SmartScreen 提示属于已知情况，但要给用户说明。

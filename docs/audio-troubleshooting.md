# 获面通：语音与电脑音频排障指南

> 麦克风转写没声音？电脑音频点不开？先看看这里。

---

## 快速自查

| 症状 | 先检查什么 |
|------|-----------|
| 麦克风按钮点了没反应 | Deepgram 配置了吗？测试通过了吗？ |
| 麦克风按钮显示"监听中"但没有文字 | 麦克风权限给了吗？选对设备了吗？ |
| 电脑音频按钮无法点击 | 当前系统是否支持？来源选了吗？ |
| 语音设置里音量条不动 | 麦克风被静音了？设备选错了？ |
| 报错"权限被拒绝" | 去 Windows 设置开权限 |

---

## 问题详解

### 1. 麦克风权限被拒绝

| 项目 | 内容 |
|------|------|
| **现象** | 点击麦克风按钮后提示"权限被拒绝" |
| **原因** | Windows 没有授予获面通麦克风权限 |
| **解决** | 1. 点击语音设置中的"授权麦克风"按钮<br>2. 在 Windows 设置 → 隐私和安全性 → 麦克风中开启权限<br>3. 确保"获面通"在允许列表中<br>4. 返回应用重新点击麦克风 |

### 2. 麦克风无输入音量

| 项目 | 内容 |
|------|------|
| **现象** | 麦克风按钮监听中，但音量条不动 |
| **原因** | 麦克风被静音、设备未插好、选择了错误的设备 |
| **解决** | 1. 检查麦克风物理开关是否打开<br>2. 检查 Windows 系统音量中麦克风是否被静音<br>3. 在语音设置的下拉列表中尝试切换设备<br>4. 使用"本地麦克风诊断"功能排查 |

### 3. 麦克风设备找不到

| 项目 | 内容 |
|------|------|
| **现象** | 设备列表为空或提示"未找到设备" |
| **原因** | 没有插入麦克风、驱动异常、或设备被其他应用占用 |
| **解决** | 1. 确认麦克风已正确插入电脑<br>2. 点击"刷新设备"重新枚举<br>3. 重启获面通后重试<br>4. 在 Windows 声音设置中确认麦克风工作正常 |

### 4. 电脑音频不支持

| 项目 | 内容 |
|------|------|
| **现象** | 点击电脑音频按钮后提示"当前系统不支持" |
| **原因** | 操作系统或音频驱动不支持屏幕/窗口音频捕获 |
| **解决** | 1. 确保 Windows 版本 >= 10 1903<br>2. 更新音频驱动<br>3. 如果仍不支持，改用麦克风转写或手动输入问题 |

### 5. 电脑音频未选择来源

| 项目 | 内容 |
|------|------|
| **现象** | 点击电脑音频后提示"请先选择来源" |
| **原因** | 未选择要捕获的屏幕或窗口 |
| **解决** | 点击语音设置中的"刷新来源"按钮，在列表中选择"整个屏幕"或具体窗口 |

### 6. Deepgram 连接失败

| 项目 | 内容 |
|------|------|
| **现象** | 点击麦克风后一直"连接中..."最终失败 |
| **原因** | Deepgram Key 不对、网络无法连接 Deepgram、免费额度用完 |
| **解决** | 1. 去设置页找到 Deepgram，点击"测试连接"<br>2. 如果测试失败，检查 Key 是否正确<br>3. 如果测试成功但转写仍失败，检查网络是否可以访问 Deepgram API<br>4. 如果返回 402 错误，说明余额不足，去 deepgram.com 充值 |

### 7. 转写过程中突然断开

| 项目 | 内容 |
|------|------|
| **现象** | 实时转写突然不更新了，但按钮还在"监听中" |
| **原因** | 网络波动、长时间无音频输入导致连接超时 |
| **解决** | 1. 先停止转写，再重新开始<br>2. 检查网络是否稳定<br>3. 如果频繁断开，尝试切换网络或使用有线网络 |

---

## 本地麦克风诊断

如果不确定麦克风硬件是否正常，可以用"本地麦克风诊断"功能：

1. 在面试台的语音设置中点击 **"本地麦克风诊断"**
2. 系统会检查：
   - 麦克风能否打开
   - 是否有输入音量
3. 诊断完成后显示具体结果
4. 这个诊断**不调用 Deepgram**，纯本地检查

---

## 最佳实践

1. **面试前**：在作战室做一键检查，确认语音链路正常
2. **面试中**：观察音量条是否有波动，确认 Deepgram 在正常转写
3. **面试后**：如果遇到问题，查看作战室下方的诊断日志

# 替代 / 保留 / 合并策略说明

> 当背景资料补全中心发现字段冲突时，用户可以选择"替代"、"保留"或"合并"三种处理方式。
> 本说明文档解释每种策略的含义和适用场景。

---

## 三种策略

### 1. 替代（Replace）

用新内容替换旧内容。

**适用场景：**
- 用户手动填写了更准确的信息
- 从公开资料获取到更可信的来源
- 旧的 AI 模拟内容被用户确认的信息替代

**操作示例：**
```
旧值：离职原因 = "个人发展"（来自简历）
新值：离职原因 = "业务调整，部门裁撤"（用户填写，更准确）
→ 替代：用新值替换旧值
```

### 2. 保留（Keep）

保留旧内容，放弃新内容。

**适用场景：**
- 旧内容来自更高可信度的来源（正式简历 > 公开资料）
- 新内容不确定或不完整
- 用户手动选择了保留

**操作示例：**
```
旧值：期望薪资 = "22-25K"（来自薪资谈判包）
新值：期望薪资 = "20K"（来自新填写的字段，可能是笔误）
→ 保留：维持 22-25K
```

### 3. 合并（Merge）

将新内容与旧内容合并，保留两种说法。

**适用场景：**
- 两个来源的信息互补而非矛盾
- 需要保留上下文以应对不同面试场景
- 一个来源提供基础信息，另一个提供补充细节

**操作示例：**
```
旧值：离职原因 = "业务调整"（来自 HR 包）
新值：离职原因 = "希望接触更大平台"（来自简历）
→ 合并：离职原因 = "业务调整 + 个人发展"（保留两种口径，灵活使用）
```

## 选择建议

| 场景 | 建议策略 | 原因 |
|------|----------|------|
| 用户确认了新信息 | 替代 | 用户确认的信息优先 |
| 旧值来自简历，新值来自 AI | 保留或复核 | AI 内容仅供参考 |
| 旧值和新值互补 | 合并 | 保留全面信息 |
| 旧值和新值矛盾 | 替代或交叉验证 | 先确认哪个是正确的 |
| 不确定选哪个 | 保留 > 合并 > 替代 | 保守策略不丢数据 |

## UI 展示

每个冲突字段显示：

```
[字段名]
  - 旧值：...（来源：...，可信度：...）
  - 新值：...（来源：...，可信度：...）
  [替代] [保留] [合并]（用户三选一）
  说明：选择建议（可选）
```

最终产品接入后，用户选择策略后系统自动处理字段更新，并将操作记录到日志。
